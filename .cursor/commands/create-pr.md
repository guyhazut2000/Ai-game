# Open a pull request

Follow the **"Pull request"** section of **docs/workflow.md**.

Do the following:

1. **Ensure the branch is pushed** — Run `git push -u origin <branch-name>` if the feature/fix branch is not yet on the remote.
2. **Draft the PR** — Prepare a pull request from the current branch into the target branch (e.g. main or develop). Use the project's PR title and description conventions from docs/workflow.md:
   - **Title:** Short, descriptive (e.g. "Add combat damage calculation", "Fix chat reconnection").
   - **Description:** What changed, why, how to test; optionally link to docs/workflow.md or PROJECT_ARCHITECTURE.md.
3. **Remind the user** — Tell them to open the PR in the host UI (GitHub/GitLab/etc.) if you cannot open it directly, and to use the drafted title and description.

Read docs/workflow.md for the full PR rules and template.
